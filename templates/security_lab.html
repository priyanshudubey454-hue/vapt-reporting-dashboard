Juice Shop live checks

Test your own local Juice Shop instance

The target must be a private lab IP already listed in Assessment details. These checks make one read-only SQL error probe or basket reads only. They do not crawl, extract database records, change baskets, or save credentials, tokens, or response bodies.

Use throwaway Juice Shop accounts only. For IDOR, create two different accounts and add one product to the basket owned by Account B. The app logs into both accounts temporarily to compare access; the passwords and tokens are discarded after the check.

Built-in practice simulator

Use this when Juice Shop is not running. It only simulates fictional results inside this dashboard.

SQL injection (SQLi)

A vulnerable search may mix typed input into a database command. Use parameterized queries so search text stays data.

Expected safe behavior: crafted search text returns no unrelated records.

IDOR / BOLA

An API must check whether the signed-in user owns or may access each requested object.

Expected safe behavior: another user's private record is denied (for example, HTTP 403).

Use real security tests only against systems you own or are authorized to assess.
